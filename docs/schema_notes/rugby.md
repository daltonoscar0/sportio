# Rugby union event data — reconnaissance notes

Recon date: 2026-08-25. Everything below was fetched live and inspected; nothing is guessed.
Raw downloads cached under `data/raw/rugbypy/` and `data/raw/espn_rugby/` (gitignored).
Committed fixtures under `tests/fixtures/rugby/`.

**Headline finding: there is no open, downloadable, spatial (x/y) rugby union event dataset.**
`rugbypy` publishes box-score aggregates only — it has no ball-by-ball table at all. ESPN publishes a
typed *scoring-and-discipline* event list (try / conversion / penalty goal / cards / substitutions) with a
match clock, a team, and one athlete per event — and **no field position of any kind**, and **no free-text
commentary**. So `sportio`'s rugby adapter can populate `type`, `t`, `period`, `team*`, `player*`,
`outcome`, and score context, but `x`, `y`, `end_x`, `end_y`, `pressure`, `body_part` are structurally NULL.

### 1.4 rugbypy gotchas (measured)

1. **Two parallel, mutually inconsistent stat vocabularies.** Columns split into an "old" family
   (`metres_carried`, `tackles_made`, `line_breaks`, `offloads`, `tackles_completed`) and a "new" family
   (`meters_run`, `tackles`, `clean_breaks`, `offload`, `missed_tackles`). Every row populates exactly one
   family and leaves the other `NaN` — in the 72-row Jac Morgan file, `points`/`rucks_won`/`runs` are NaN
   for club rows and populated for Wales rows. Note the metres/meters spelling split.
2. **IDs are unstable hashes and do not join across files.** The live `competition_registry.parquet` has
   `d0f3c9d2 = "Top 14"`, `ab1bbd78 = "United Rugby Championship"`, `38d2154f = "European Champions Cup"`.
   The match file for `35e0b16d` carries `competition_id = "ee0c6883"` with `competition =
   "European Rugby Champions Cup"` — an id **absent from the registry** and a different display name.
   The player file has `competition_id = "50e6935b"` with `competition = "United Rugby Championship"`,
   while the README's printed registry says `50e6935b = "World Rugby U20 Championship"`.
   Conclusion: **trust the inline `competition` / `team` name strings, not the `*_id` columns**, and never
   cache ids across a refresh. Also `competition_name` is not unique — `"Premiership Cup"` appears 5 times
   with 5 different ids (`15d56a95, 7e010b9d, bb375c1f, 8832026e, 23728032`).
3. The registry has 22 rows live; the README's rendered table shows 23 different ones. The repo is rebuilt
   daily and the README snapshot is stale.
4. `team.py` uses `github.com/.../blob/...?raw=true` while every other module uses
   `raw.githubusercontent.com`. Both resolve, but a loader that only allow-lists one host will break.
5. `pyarrow` is required to read these; `pandas==2.3.3` / `pyarrow==19.0.0` are hard-pinned in the package
   metadata, so do **not** depend on `rugbypy` itself — hit the parquet URLs directly.

### 2.1 League discovery

17567, 242041, 289271, 289272, 289277, 289279, 270555, 270563, 236461, 289274, 282, 283, 289237, 289262,
289234`.

### 2.2 Working endpoints (both verified HTTP 200 with real content)

```
https://site.api.espn.com/apis/site/v2/sports/rugby/{league_slug}/scoreboard?dates={YYYYMMDD}
https://site.api.espn.com/apis/site/v2/sports/rugby/{league_slug}/summary?event={event_id}
http://sports.core.api.espn.com/v2/sports/rugby/leagues/{league_slug}/events/{event_id}/competitions/{event_id}/plays?limit=500
```

Verified example: `?dates=20250201` on slug `180659` →
`600251` Scotland vs Italy (STATUS_FINAL, Scottish Gas Murrayfield) and
`600252` Ireland vs England (STATUS_FINAL, Aviva Stadium).

**Date ranges do not work.** `?dates=20250201-20250320` returned HTTP 200 with `events: []` (885 bytes) —
you must iterate single `YYYYMMDD` values.

### 2.3 The play list: exact JSON path

**Summary (richest form):**
```
$.header.competitions[0].details        -> list, 58 items for event 600252
```
Sibling flags on `$.header.competitions[0]`:
`commentaryAvailable: false`, `liveAvailable: false`, `boxscoreSource: "full"`, `playByPlaySource: "full"`.

**Scoreboard (lighter, but one request covers every match of the day):**
```
$.events[i].competitions[0].details     -> 48 items for 600251, 58 for 600252
$.events[i].competitions[0].playByPlayAvailable  -> true
```

**Core API (same rows, plus a stable play id):**
```
$.items[]   -> count: 58 (identical to the summary details)
$.items[i].id          e.g. "1705632"
$.items[i].$ref        .../plays/1705632
$.items[i].modified    e.g. "2025-06-22T23:41Z"
```
Core-API `team` and `participants[].athlete` are `$ref` links, not inline objects — the site summary is
easier to consume.

### 2.4 Fields of a single play — real, unedited

From `$.header.competitions[0].details[2]` of event 600252:
```json
{

 "type": { "id": "1", "text": "try" },
 "awayScore": 5,
 "homeScore": 0,
 "period": { "number": 1 },
 "clock": { "value": 521.0, "displayValue": "9'" },
 "team": {
  "id": "1", "uid": "s:300~t:1",
  "name": "England", "abbreviation": "ENG", "displayName": "England"

```

Key frequency across all 58 details of 600252 — every key present on every row, no optional fields:
`sequenceNumber(58) type(58) awayScore(58) homeScore(58) period(58) clock(58) team(58) participants(58) addedClock(58)`.

The **scoreboard** variant of `details` is a *different, smaller* shape — only 4 keys, and it renames the
athlete list:
```json
{
 "type": { "id": "1", "text": "try" },
 "clock": { "value": 494.0, "displayValue": "9'" },

```

`athletesInvolved` where summary uses `participants[].athlete`. A loader must handle both or only use

### 2.6 Clock semantics (measured, important)

`$.format` on the summary:
```json
{"regulation": {"periods": 2, "displayName": "Half", "slug": "half", "clock": 2400.0}}
```

`clock.value` is **elapsed seconds since kickoff of the match, NOT reset at half time**. Measured on 600252:

| | n | min `clock.value` | max `clock.value` |
|---|---|---|---|
| `period.number == 1` | 11 | 233.0 | 2419.0 |
| `period.number == 2` | 47 | 2402.0 | 4918.0 |

Note period 1's max (2419 s = 40:19) **exceeds** period 2's min (2402 s = 40:02) — first-half added time
overlaps the nominal 2400 s boundary, so you cannot infer `period` from the clock; use `period.number`.

Therefore, for the canonical `t` (seconds **within** period):
```
t = clock.value - (period.number - 1) * format.regulation.clock      # 2400.0
```
which gives `t ∈ [2.0, 2518.0]` for this match. `addedClock.value` was `0.0` on all 58 rows here, so its
meaning is unverified — treat it as an additive stoppage offset and carry it into `extra`.

`clock.displayValue` is minute-ceiling with an apostrophe: `233.0 -> "4'"`, `521.0 -> "9'"`. Do not parse it.

`sequenceNumber` is the string `"0"` on **every** row — it is useless for ordering. Preserve array order
(the array is already in ascending clock order across periods).

### 2.7 What is NOT available

- **No x/y, no field position, no metres-from-own-line, no zone, no pitch reference of any kind.**
  A recursive walk of the full 635 KB summary collects **171 distinct key names**; matching them against
  `/(coord|^x$|^y$|xy|field|yard|metre|meter|distance|zone|pitch|location)/i` returns the **empty set**.
  (`meters_run` etc. exist only as `boxscore` *stat names*, not as event geometry.) This is the biggest gap:
  `sportio`'s `x`/`y`/`end_x`/`end_y` cannot be populated from ESPN rugby at all.
- **No free-text commentary.** `commentaryAvailable` is `false`, and adding
  `&enable=commentary,plays,keyEvents` to the `site.web.api.espn.com` summary returned a
  **byte-identical 634 966-byte** response with no `commentary`, `plays` or `keyEvents` key — the enable
  flags are ignored for rugby. So the "derive type from keyword rules over commentary text" fallback is
  *not* available here; there is nothing to parse.
- **No open-play events.** No carries, passes, rucks, mauls, lineouts, scrums, tackles, turnovers, or
  knock-ons appear as *events*. They appear only as **match totals** in `$.boxscore`.
- No possession/phase chain, no ball-in-play, no set-piece outcome.

### 2.8 Useful supporting objects in the same summary

- `$.header.competitions[0].competitors[]` → `{id, homeAway, winner, score, team:{id,displayName,abbreviation}, linescores[]}`.
  Measured: competitor `id "3"` Ireland home 27 (winner), `id "1"` England away 22.
  `details[].team.id` joins directly onto `competitors[].team.id`.
- `$.rosters[]` → `{homeAway, winner, team, roster[]}`, each roster entry
  `{active, starter, jersey, athlete:{id, fullName, displayName, shortName}, position:{name,displayName,abbreviation}, captain, subbedIn, subbedOut, stats[]}`.
  Example: `{"jersey":"15","athlete":{"id":"285683","fullName":"Hugo Keenan"},"position":{"name":"fullback","abbreviation":"FB"}}`.
  This is the **only** source of jersey numbers and positions — join on `athlete.id`.
- `$.boxscore.teams[].statistics[].stats[]` and `$.boxscore.players[].statistics[].athletes[].statistics[].stats[]`
  → `{name, displayName, shortDisplayName, description, abbreviation, type, value, displayValue}`,
  e.g. `{"name":"cleanBreaks","type":"cleanbreaks","value":10.0,"displayValue":"10"}`.
- `$.gameInfo` → `{venue, attendance}`; `$.header.season` / `$.events[i].season` →
  `{"year": 2025, "type": 1, "slug": "2025-six-nations"}`.

## 4. Proposed mapping to the canonical `events` schema

Source of record: ESPN `summary?event=` → `$.header.competitions[0].details[]`, one canonical row per detail.

| canonical column | source | notes |
|---|---|---|
| `match_id` | `str(event_id)` from the scoreboard / `$.header.id` | e.g. `"600252"`; prefix with `"espn_rugby:"` if namespacing |
| `competition` | `$.header.league.name` or scoreboard `$.leagues[0].name` | e.g. `"Six Nations"` |
| `season` | `$.header.season.year` (int) | `2025`; `$.header.season.slug` = `"2025-six-nations"` → `extra` |
| `team_id` | `details[].team.id` | `"1"`, `"3"` — ESPN team ids, join to `competitors[].team.id` |
| `team` | `details[].team.displayName` | summary only; scoreboard gives only `team.id` |
| `player_id` | `details[].participants[0].athlete.id` | `"292217"`; always exactly 1 participant (measured: 58/58 rows had `len(participants)==1`) |
| `player` | `details[].participants[0].athlete.displayName` | |
| `t` | `details[].clock.value - (period.number-1)*format.regulation.clock` | seconds within period; see §2.6 |
| `period` | `details[].period.number` | `1` or `2`; **absent in the scoreboard variant** |
| `type` | mapped from `details[].type.id` — table below | |
| `subtype` | see table | mostly NULL |
| `x`, `y`, `end_x`, `end_y` | **NULL** | source has no coordinates whatsoever |
| `outcome` | see table | derivable only for kicks-at-goal and substitutions |
| `pressure` | **NULL** | no such concept in the feed |
| `body_part` | **NULL** | not recorded |
| `extra` | JSON of `{"espn_type_id","espn_play_id","home_score","away_score","added_clock","clock_value","clock_display","sequence_number"}` | keep `homeScore`/`awayScore` here — they are the running score *after* the event |

### 4.1 `type.id` → canonical `type`

| `type.id` | `type.text` | canonical `type` | `subtype` | `outcome` |
|---|---|---|---|---|
| `1` | `try` | `try` | NULL | `success` |
| `2` | `conversion` | `conversion` | NULL | `success` (only made kicks are emitted — a missed conversion produces no detail row; the 600252 match has 7 tries but only 4 conversions) |
| `3` | `penalty goal` | `penalty_goal` | NULL | `success` |
| `4` | *(unobserved)* | `drop_goal` | NULL | `success` — **verify before shipping** |
| `5` | `yellow card` | `card` | `yellow` | NULL |
| `6` | *(unobserved)* | `card` | `red` | NULL — **verify before shipping** |
| `7` | `player substituted` | `substitution` | `off` | NULL |
| `8` | `substitute on` | `substitution` | `on` | NULL |

Unmapped and therefore **permanently empty** for this source:
`carry, pass, kick, ruck, maul, lineout, scrum, tackle, turnover, penalty, knock_on`.
Those 11 of the 16 vocabulary terms have no representation in any open rugby feed found.

### 4.2 Pairing substitutions

`type.id` 7 (`player substituted` = the player coming **off**) and 8 (`substitute on`) always arrive as a
pair sharing the same `clock.value`, `period.number` and `team.id` — measured on 600252: 22 of each, and
grouping by `(team.id, period.number, clock.value)` yields exactly 22 groups of `{7, 8}` with no
collisions. All 22 pairs are **adjacent in array order and always ordered `8` (on) then `7` (off)** — i.e.
the incoming player is listed first. Both the `(team.id, period.number, clock.value)` join and array
adjacency work; prefer the explicit join, it is robust to two simultaneous substitutions by the same team.
Emit two canonical rows (`subtype = "on"` / `"off"`) and cross-reference the partner's `player_id` in
`extra` — do not try to fold them into one row.

Watch out for the HIA/reversal pattern: in 600252 Henshaw comes on for Hansen at 233 s and Hansen comes
back on for Henshaw at 996 s, so the same `player_id` legitimately appears with both `on` and `off`.

### 4.3 Enrichment joins worth doing

- jersey / position: `$.rosters[].roster[]` on `athlete.id` → gives `jersey`, `position.abbreviation`,
  `starter`, `captain`. Not part of the canonical events schema but belongs in `extra`, and it is required
  if a rugby `tracking` frame is ever added.
- `team` name when reading from the scoreboard: `details[].team.id` → `competitions[0].competitors[].team.displayName`.

### 4.4 If a commentary-text source is ever found

ESPN rugby has none (§2.7), so this is currently hypothetical. Were a text feed found, the keyword rules
would be (case-insensitive, first match wins, most-specific first):

```
knock_on      : "knock on", "knock-on", "knocks on", "spills", "fumbles forward"
try           : r"\btry\b" and not "try line" / "no try" / "try saving"
conversion    : "conversion", "converts"
penalty_goal  : "penalty goal", "kicks the penalty", "slots the penalty", "3 points"
drop_goal     : "drop goal", "drop-goal", "dropped goal"
card          : "yellow card", "red card", "sin bin", "sin-bin"
substitution  : "replaces", "comes on for", "substitution", "off for"
scrum         : "scrum"
lineout       : "lineout", "line-out", "throws in", "at the tail", "overthrow"
maul          : "maul", "driving maul", "rolling maul"
ruck          : "ruck", "breakdown", "jackal"
penalty       : "penalty" (after penalty_goal), "offside", "not releasing", "high tackle"
turnover      : "turnover", "wins the ball back", "steals"
tackle        : "tackled", "tackle", "brought down", "held up"

```
Field position, if the text carries it (`"on the 22"`, `"inside their own 10"`, `"5m out"`), would map to
`x` in metres from the attacking team's own goal line; `y` would still be NULL. This would be a lossy,
low-confidence derivation and should set a `derived_from_text: true` flag in `extra`.
